# Starboard 产品验收报告（Round 4）

- 被测产品：Starboard — https://star-history-3wn.pages.dev
- 定位：不搜仓库、不写代码，60 秒看懂现在什么技术最火
- 验收角色：严苛验收官（傻瓜用户 / ADHD 用户 / 暴躁用户 三重视角）
- 验收日期：2026-10-26
- 验收环境：Linux 沙箱，Chrome 150.0.7871.181（CDP 127.0.0.1:9222），Node v24
- 验收方式：**真实操作**（CDP 驱动点击 / 键盘输入 / 截图 / 网络与控制台事件采集），非代码推测

## 一、验收方法

自研 CDP 驱动脚本（`/workspace/acceptance/round-4/`）：
- `cdp.js`：通用页面加载 + 布局溢出检测 + 控制台/网络采集 + 截图
- `click-cards.js`：首页 20 张卡片逐一真实点击
- `search-test.js`：5 种搜索场景真实键盘提交
- `action-test.js`：汉堡菜单 + 详情页三操作 + 下载行为

每次测试新建浏览器 target 并清理缓存/Cookie，满足隔离要求。

**F3 判定说明（边界判断，已按"宁可误报"处理）**：项目名本身属"内容"，但首页以 `owner/ repo`

"未解释的技术术语"。若产品方主张"项目名即内容"，此条可降级为 P1；本轮从严判定为触发。

## 五、验收前自检（四问）

1. **我是不是在用开发者视角代替傻瓜用户视角？**
   初始确有倾向（曾把 repo slug 视为"项目名内容"而放过）。已通过 F3 判定修正：以"完全不懂技术的
   傻瓜用户"视角看，`owner/ repo` 格式与整段英文描述确属未解释的技术黑话。
2. **我是不是因为"功能很强"放低了可用性标准？**
   未放低。虽认可其零输入可用性与视觉完成度（D2/D3 满分），仍抓出静默失败与品牌错位两类硬伤。
3. **有没有哪条扣分是我主观喜好而非真实用户问题？**
   「分享指向 x.com」对境内用户是真实可用性问题，但对全球用户不是，故仅列 P2，未计入 P0/P1；
   「赞助位英文」属第三方内容，已标注可豁免。
4. **如果我是暴躁用户，会在第几步关掉页面？**
   第 3–4 步：打开首页（好看，留下）→ 想查具体项目，但首屏无搜索框、需长滚动才找到 →
   输入项目名回车 → **页面毫无反应、无任何提示** → 判定卡死并关闭。

## 六、最严重的 3 个问题

1. **详情页顶部品牌 logo 画面为 `star-history.com`**，与 Starboard 定位直接矛盾，属品牌级错位（P0-2）。
2. **异常搜索 4 种场景全部静默失败**（不跳转、无中文提示、无报错），用户误以为卡死（P1-1）。
3. **首页首屏 repo slug + 整段英文描述未解释**，触发 F3（P0-1）。
