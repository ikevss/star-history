## 三、各维度评分与理由

### D1 首屏价值传达（20 → 14）
**优点**：h1「现在什么技术在起飞？」+ 副标题「不用搜、不用注册。打开就能看到全球开源项目里，谁在涨、涨多快。」定位清晰；首屏即展示 3 张带增速的卡片，傻瓜用户也能一眼看懂"这是个榜单"。
**扣分**：核心结论"13/20 是 AI"不在首屏（I-11）；"关注"这一关键指标无解释（I-07）。
**证据**：`01-desktop-1440.png`、`03-mobile-375.png`。

### D2 零输入可用性（20 → 13）
**优点**：不搜索、不注册、不点击即可获得完整 top20 榜单 + 增速 + 领域筛选，符合产品定位，是产品最强项。
**扣分**：首页 15%（3/20）卡片是死链（I-01）；数据标注"本周"却为 7 个月前（I-04）；底部延展功能（搜索）对目标用户是死路（I-03）。零输入虽能拿到信息，但拿到的信息有相当比例不可用/过期。

### D3 核心任务完成时间（20 → 18）
实测：FCP 2296ms、load 3595ms、卡片就绪 3597ms。核心任务"知道现在什么技术最火"≈3.6s 完成，远优于 60s 目标。仅因 FCP 偏慢扣 2 分（I-12）。

### D4 理解成本（15 → 6）
**严重**：首页中文，但 header（How to use this site / Blog）、底部搜索框 placeholder 与按钮（View star history）、卡片详情页、404 页、token 弹窗全为英文（I-06）；token 弹窗还自称 "Star-history"（品牌错乱）。指标"关注/共 X 万/9,647"无图例（I-07）。日期格式三处不一致（I-08）。对"完全不懂技术的傻瓜用户"和中文用户理解成本很高。

### D5 视觉与信任感（15 → 7）
**优点**：xkcd 手绘风格统一、亲和，卡片层次清晰，视觉完成度高。
**扣分**：3 张死链 + "not found" 页（I-01）；"Access Token Unauthorized" 橙色报错 + 英文弹窗（I-03）；"本周数据"过期 7 个月（I-04）；375px 布局裁切（I-05）。这些直接摧毁信任。

### D6 情绪体验（10 → 5）
视觉愉悦带来正向情绪；但暴躁用户会在点击死链（"not found"）或搜索被要求"去 GitHub 建 token"时产生强烈挫败与被欺骗感（与"不用注册"承诺冲突）。

## 五、验收前自检（按题目要求逐条自问）

1. **我是不是在用开发者视角代替傻瓜用户视角？**
   部分风险存在：例如判定"关注 = GitHub star"时参考了源码逻辑。已通过三档人设（傻瓜 / ADHD / 暴躁）逐屏代入复核，尤其对"关注""9,647""本周数据"等按"不知道 GitHub 为何物"的用户重新判定，最终保留为 I-07 并在 D4 扣分。

2. **我是不是因为"功能很强"放低了可用性标准？**
   没有。榜单/筛选功能确实强，但死链、token 死路、过期数据、移动端裁切属于硬缺陷，未因"功能强"而放宽。

3. **有没有哪条扣分是我主观喜好而非真实用户问题？**
   逐条复核：视觉风格（xkcd）为主观偏好，但**未据此扣分**（D5 反而给了加分项）；I-08 日期格式、I-10 截断、I-06 语言混杂均为可复现的真实可用性问题；I-07 裸数字 9,647 虽偏主观，但"用户看到无法理解的无标签数字"是真实困惑点，予以保留但降级为 P2。

4. **如果我是暴躁用户，会在第几步关掉页面？**
   首屏不会关（视觉吸引、加载快）；最可能在**点击第 12/15/17 张卡片看到 "not found"** 时（尤其连续遇到）关掉；次高概率在**底部搜索被要求填写 GitHub token** 时关掉——这两处均为强烈负面情绪触发点。

**自检后校准**：维持总分 **63**，判定 **不通过**。未因自检上调或下调。
